# 节点监控：目标与需求沉淀

## 1. 产品目标

用一个轻量、可独立启动的 Windows 软件持续观察 Clash/mihomo 节点的可达性和延迟，减少手工点测；用户可以通过最近状态、1/3/7 天趋势和原始 CSV 判断哪个节点更稳定，并把数据交给 AI 做进一步分析。

## 2. 目标分布

| 目标层 | 用户要解决的问题 | 产品回答 | 验收信号 |
| --- | --- | --- | --- |
| 核心目标 | 节点什么时候稳定、什么时候失速 | 持续采样并保留每个节点的状态和延迟 | 可查询最近结果和历史趋势 |
| 决策目标 | 当前应该优先使用哪个节点 | 突出可用数、平均延迟、异常数和当前节点 | 10 秒内能找到可用节点 |
| 诊断目标 | 不稳定是偶发还是持续 | 支持整体最佳趋势、单节点、日期窗口和聚合 | 能看出超时簇、恢复时间和跨日模式 |
| 操作目标 | 不想每次手动点击测试 | 启动后自动周期采样，并支持立即刷新/暂停 | 不需要 AI 或人工持续触发 |
| 路由目标 | 节点失速时希望回到可用线路 | 可选开启自动路由并显示实际回读结果 | 关闭时绝不调用选择接口 |
| 分发目标 | 不想安装复杂开发环境 | 提供 EXE，启动后自动打开控制台 | 双击即可进入页面 |

## 3. P0 必须满足

1. 默认 60 秒采样一次，支持调整；启动后立即采样。
2. 识别并监控可用的叶子节点，策略组不作为独立节点。
3. 每次记录节点名、采样时间、状态、延迟和必要的错误摘要。
4. 把超时和失败保留为明确断点，不能静默丢失。
5. 提供当天、最近 3 天和 7 天趋势；展示聚合不能改变后台原始采样。
6. 默认只读、本机运行、不上传数据、不调用 AI 常驻服务。
7. 首次启动自动打开控制台；自动连接失败时可填写地址/密钥并测试。
8. 趋势区一键导出当前时间范围的原始 UTF-8 CSV，至少包含时间、节点、状态、延迟、请求耗时和错误字段。
9. 支持深色和浅色主题，离线、采样中、暂停、错误和无历史都显示解释性状态。

## 4. P1 首版能力

- 控制台显示可用数、平均延迟、异常数、最近刷新时间和下一次刷新倒计时。
- 节点列表显示文字状态、延迟、采样时间和错误说明，状态不只依赖颜色。
- 图表支持节点聚焦、时间缩放、拖拽、键盘平移和点位提示。
- 自动路由开关默认关闭；开启后遵守连续异常、绿色候选、冷却记录和实际回读合同。
- 支持 `--once`、`--no-ui`、可选桌面浮点和 `run_monitor.bat`。
- EXE 不要求 Node.js；`web/` 随 EXE 打包。

## 5. 非功能需求

| 维度 | 要求 |
| --- | --- |
| 轻量化 | Python 标准库、有限线程、本地 SQLite |
| 网络负载 | 每个周期只对目标节点发起一次延迟探测 |
| 数据量 | 默认保留 30 天明细并自动清理过期行 |
| 安全 | 密钥不进 Git；控制器和 Web 服务默认使用本机回环地址 |
| 可恢复 | 控制器暂时不可用时显示错误并保留旧数据 |
| 可解释 | 正常、超时、失败分别显示 |
| 低误判 | 完整周期完成后才替换最近快照 |

## 6. 验收标准

- [x] 启动服务或 EXE 后自动打开本机控制台。
- [x] 自动发现失败时可以在页面填写控制器地址/密钥并执行连接测试。
- [x] 关闭控制器时工具不崩溃，显示连接失败并保留旧数据。
- [x] 1/3/7 天趋势无数据时显示空状态，不伪造曲线。
- [x] 导出范围跟随当前 1/3/7 天选择，且不受展示聚合影响。
- [x] 深色和浅色主题都能完成主要操作。
- [x] 关闭自动路由时不调用选择接口；开启后显示实际回读节点。
- [x] 公开仓库不包含密钥、真实配置、SQLite 数据或私人路径。
