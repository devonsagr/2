# 节点监控：目标与需求沉淀

## 1. 原始目标

用户当前 Clash 机场中台湾（TW）节点的 IP 相对纯净，但网络质量不稳定。目标是用一个轻量脚本持续观察这些节点的流畅度，减少手工点测，并通过最近状态和每日 24 小时趋势帮助选择稳定节点。

截图仅作为界面参考：

- “a”表示 Clash 界面中的延迟/测速触发入口。
- “b”表示每个节点返回的结果，例如延迟或 `Timeout`。
- 截图上的红色手写标记不是执行指令，也不是额外的产品需求。

## 2. 目标分布

| 目标层 | 用户要解决的问题 | 产品回答 | 验收信号 |
| --- | --- | --- | --- |
| 核心目标 | TW 节点什么时候稳定、什么时候失速 | 持续采样并保留每个节点的状态和延迟；趋势主视图聚合所有节点中每个时间点的最佳可用延迟 | 可查询任意节点的最近结果、最佳整体趋势和 1/3/7 天历史 |
| 决策目标 | 当前应该优先使用哪个节点 | 卡片突出可用数、平均延迟、最近异常，并列出节点结果 | 10 秒内能找到可用且延迟较低的节点 |
| 诊断目标 | 不稳定是偶发还是持续 | 主图看整体最佳趋势，按需切换单节点、日期范围和聚合粒度 | 能看出整体低延迟趋势、某节点超时簇、恢复时间和跨日模式 |
| 操作目标 | 不想每次手动点击测试 | 脚本自动按周期运行，并支持立即刷新/暂停 | 不需要 AI 或人工持续触发 |
| 路由目标 | 节点失速时希望自动回到可用线路 | 用户可选开启自动路由；绿色当前节点保持不动，橙色按确认次数切到绿色候选，首次 Timeout/错误立即故障转移且不被旧冷却阻挡 | 关闭时绝不调用 Clash 选择接口；开启后每次动作有记录 |
| 资源目标 | 长时间运行不能拖慢电脑 | 标准库、少量线程、本地 SQLite、定期清理 | 无大依赖；默认只保留 30 天数据 |

## 3. 需求分层

### P0：必须满足

1. **定时监控**：默认每 60 秒采样一次，支持改为 30 秒；启动后立即采样。
2. **节点范围**：默认监控名称匹配 `^TW-\d+$` 的叶子节点，即当前截图中的 `TW-1`～`TW-10`；策略组 `TW自动选择`、`TW负载均衡`不作为独立叶子节点采样。
3. **结果记录**：每次记录节点名、采样时间、状态（正常/超时/失败）、延迟毫秒数和必要的错误摘要。
4. **超时识别**：把 Clash API 的超时返回记录为 `Timeout`，不能把失败节点静默丢掉。
5. **历史趋势**：默认绘制当天 00:00～24:00 的“所有节点中最佳可用延迟”线性趋势，并能切换最近 3 天/7 天；默认按 30 分钟聚合以降低后台渲染压力，仍可手动选择 1 分钟、30 秒、5/15 分钟等粒度查看细节，正常延迟与超时/失败要可区分。
6. **本地运行**：监控由脚本线程完成，不调用 AI，不上传数据，不修改 Clash 配置。

### P1：首版应交付

1. **仪表盘卡片**：置顶桌面卡片显示可用数、平均延迟、异常数、最近刷新时间和下一次刷新倒计时。
2. **最近结果列表**：列出每个 TW 节点最近一次的延迟或 `Timeout`，状态不能只依赖颜色。
3. **历史图入口**：从卡片查看 1/3/7 天历史；图表默认显示所有节点的最佳趋势，也可切换单节点。
4. **图表视窗**：默认 30 分钟聚合，同时支持手动选择 1 分钟、30 秒、5/15/30 分钟等粒度；时间缩放为 1×～48×，放大后可拖拽或键盘平移；Ctrl+滚轮无需先点击图面，不显示丑陋的焦点蓝框，并在点位悬停时显示节点、延迟、状态和时间。
5. **控制操作**：支持立即刷新、暂停/继续监控、关闭程序；窗口默认始终置顶但不强制修改 Clash。
6. **自动发现**：优先发现 Clash Verge 的本地控制器地址和密钥，减少首次配置；支持 JSON 配置覆盖。
7. **无界面模式**：支持 `--no-ui`，用于任务计划或后台常驻；支持 `--once` 进行一次实测。
8. **自动路由**：卡片中可选择开启或关闭；开启后默认监控 `TW自动选择`，当前节点为橙色时连续异常达到阈值且存在绿色候选才切换，首次完整采样为超时或错误时立即从绿色候选中故障转移，二者都不受上次切换冷却阻挡。
9. **保持稳定节点**：当前节点只要在线且处于绿色，即使不是延迟第一名也不切换；橙色或失败才进入路由判断。
10. **路由可解释**：卡片显示当前节点、异常连续次数、最近动作和原因；路由动作只写本地审计表，不把切换伪装成普通刷新。
11. **桌面入口**：服务和采样线程只有一套；可选启动轻量可拖拽浮点，悬停显示 Clash 当前节点和最近延迟，点击查看趋势，右键关闭，不强制占用桌面。
12. **AI 分析导出**：独立 Web 趋势区提供一键导出；按当前选中的 1/3/7 天范围导出原始 UTF-8 CSV，至少包含采样时间、节点、状态、延迟、请求耗时和错误字段；图表聚合只影响展示，不得丢失原始采样。

### P2：后续可选

- 节点评分、稳定性排序和按时间段的可用率统计。
- 超时连续发生时的 Windows 通知或声音提醒。
- 按任意自定义日期查看图表。
- 监控 TCP/UDP/HTTPS 多种探针并区分“测速可达”和“实际业务流畅”。
- Windows 通知和声音提醒。

## 4. 非功能需求

| 维度 | 要求 |
| --- | --- |
| 轻量化 | 仅使用 Python 标准库；默认 4 个测试线程，不启动浏览器服务，不保存原始网页内容 |
| 网络负载 | 每个周期只对目标叶子节点发起一次延迟探测；默认单节点超时 5 秒 |
| 数据量 | SQLite 保存明细；默认保留 30 天并自动清理过期行 |
| 安全 | API 密钥只从本地配置读取，不写入 Git；控制器默认绑定本机回环地址 |
| 可恢复 | Clash 控制器暂时不可用时，卡片显示错误和上一次数据，不删除历史记录 |
| 可解释 | `Timeout`、API 错误、正常延迟分别显示，不把所有非 200 结果混为“卡顿” |
| 低误判 | 手动刷新期间不发布半轮数据；只有整轮节点结果齐备后才替换最近快照 |
| 路由安全 | 自动路由默认关闭；启用后有橙色连续异常阈值、绿色候选、切换时间记录和本地动作记录，Timeout/error 首次完整采样即可故障切换，且不被旧冷却阻挡 |

## 5. 关键决策与假设

- **采样方式**：不模拟鼠标点击，直接调用 Clash/mihomo External Controller 的 `/proxies/{name}/delay` 接口；这等价于截图中的测速动作，但更轻、更可重复。
- **探针地址**：默认使用 `http://www.gstatic.com/generate_204`，可在本地配置文件中替换。
- **控制器**：当前环境已检测到 Clash Verge 的 `127.0.0.1:9097` 和 mihomo；脚本会读取 Clash Verge 配置中的 `external-controller` 与 `secret`，不硬编码密钥。
- **展示形态**：当前工作区没有 Clash Verge 前端源码，因此“仪表盘卡片”实现为独立本地桌面卡片，不声称修改了第三方 Clash Verge 内置页面。
- **时间间隔**：默认 60 秒；30 秒属于允许的配置值。若一次全节点测速超过周期，下一轮在本轮结束后再开始，避免并发堆积。
- **刷新语义**：手动刷新只发起请求，不清空最近完整周期；刷新按钮在忙时禁用，服务返回 busy，完成后一次性更新卡片。
- **自动路由**：路由默认关闭，用户在仪表盘明确开启后才允许使用 Clash PUT。当前绿色节点保持不动；当前节点橙色时累计异常并达到阈值后，在监控组的绿色候选中选延迟最低者；当前节点首次完整采样为 Timeout/error 时立即执行同样的故障转移；`route_cooldown_seconds` 只保留为切换时间记录，不阻挡故障恢复。
- **实际出站组**：`route_group` 可能是 `URLTest` 子组，不能直接当成实际流量选择器。脚本读取 Clash 当前 `/rules` 的 `MATCH` 目标，解析出真正承载默认流量的 `Selector`（本机为 `主代理`），只对该组执行切换。
- **路由事实**：自动路由写入 Clash External Controller 后必须立即 GET 回读控制 Selector，并再次解析最终有效 `now`；卡片与浮点显示回读到的实际节点，而不是只显示脚本计划切换的目标。开启开关后立即读取一次当前路由，避免停留在“读取中”或旧节点。
- **手动操作优先**：脚本在 PUT 前再次读取 Clash；如果用户在评估期间手动选择或改变规则路径，本轮放弃写入并同步新选择。刷新测速只读控制器，不会单独触发自动路由。
- **趋势聚合**：历史 API 通过 `bucketSeconds` 返回指定粒度；卡片默认请求 `1800` 秒（30 分钟）聚合以减少 SVG 点数和渲染压力，仍允许独立选择 `60` 秒（1 分钟）、30 秒、5/15/30 分钟，不改变后台采样频率；“跟随采样”仍作为显式选项保留。
- **数据含义**：这是探针延迟/可达性，不等同于完整带宽测速；它适合判断稳定性和响应速度，不代表下载速度。

## 6. 数据流

```text
Clash Verge/mihomo API
        │ 读取节点清单 + delay 测试
        ▼
监控线程（低频、有限并发）
        ├── 写入 data/tw_monitor.sqlite3
        │       └── route_events（仅在用户开启且实际有动作时）
        └── 通知仪表盘卡片
                    ├── 最近一次状态
                    ├── 1/3/7 天历史线图
                    ├── 当前范围原始 CSV 导出
                    └── 路由状态与最近动作
```

## 7. 验收标准

- [ ] 在当前 Clash Verge 正常运行时，能自动识别 `TW-1`～`TW-10`。
- [ ] 执行一次采样后，每个目标节点都有延迟或 `Timeout`/失败结果。
- [ ] 卡片显示最近刷新时间、可用数、异常数和每个节点的文字状态。
- [x] 1/3/7 天历史图能显示对应日期样本；无样本时明确显示空状态，而不是伪造曲线；主图显示各节点每个时间点的最佳可用延迟，支持单节点切换。
- [ ] 关闭 Clash API 后，工具不崩溃，显示连接失败并保留旧数据。
- [ ] `--once`、`--no-ui`、暂停/立即刷新可用。
- [ ] 测试不需要 AI 常驻，也不把密钥打印到控制台或写入版本库。
- [x] 关闭自动路由时不调用 Clash 选择接口；开启后绿色当前节点保持不动。
- [x] 当前节点橙色达到确认次数，或首次完整采样为超时/错误，且存在绿色候选时切换，并记录 from/to/reason；不被旧冷却阻挡；无绿色候选时保持原路由。
- [ ] 刷新未完成前仍显示上一轮完整数据，不能用半轮结果替换快照。
- [x] 仪表盘卡片在夜间主题下可读、可滚动，外层工具栏不遮挡正文；放大态可切换 1/3/7 天、聚合粒度、缩放和拖拽线性图；Ctrl+滚轮无需点击且不绘制焦点蓝框；浮点可单独关闭并显示当前节点/延迟。
- [x] 独立 Web 趋势区可按当前 1/3/7 天范围一键导出原始 UTF-8 CSV；文件包含 `sampled_at_local`、`node`、`status`、`delay_ms`、`request_ms`、`error`，且导出不受图表聚合粒度影响。

## 8. 当前状态与证据

- 已落地：Obsidian `tw-monitor` 卡片支持 1/3/7 天历史、最佳整体趋势/单节点切换、默认 30 分钟聚合与手动 1 分钟等细粒度切换、1×～48×时间缩放，以及无需点击的 Ctrl+滚轮、拖拽、键盘平移和点位 tooltip。
- 已修正：夜间 Canvas 卡片身份签改为深色高对比样式，去除白底黑字和折纸裁切；compact/full 均有统一深色外框、内框、留白和低干扰滚动条；正文、节点列表和设置不与外层卡框竞争滚动；标题统一为“节点监控”；自动路由开关点击后立即保存并回读 Clash 实际当前节点；橙色延迟按确认次数切换，Timeout/error 首次完整采样就故障转移且不被旧冷却阻挡；折线焦点不再出现蓝色框；桌面浮点悬停显示当前节点与延迟；URLTest 子组不再被误当成最终出站组。
