# 架构说明

## 组件

- `tw_monitor.py`：单文件标准库实现，包含配置解析、Clash API 客户端、监控线程、SQLite 存储、loopback API、同源静态文件服务和可选的 Tk 浮点。
- `web/index.html`、`web/styles.css`、`web/app.js`：独立 Web 控制台；无 Node.js、构建器、第三方 CDN 或 Obsidian 运行时依赖。
- `monitor_config.example.json`：可选配置模板；真实配置 `monitor_config.json` 被 Git 忽略。
- `data/tw_monitor.sqlite3`：本地采样明细和周期摘要。
- `tests/test_tw_monitor.py`：不访问真实网络的单元测试。

## API 选择

Clash Verge 当前运行 mihomo External Controller。脚本读取 `/proxies` 获得节点清单，再对每个叶子节点请求：

```text
GET /proxies/{url-encoded-node-name}/delay?url={probe-url}&timeout={timeout-ms}
```

API 返回正常延迟时记录毫秒数；HTTP 408/504 或连接超时记录为 timeout；其他错误记录为 error。每一轮完整测量结束后才发布新快照，因此手动刷新等待期间卡片继续显示上一轮完整结果，不会把半轮结果误当成最新状态。

默认只观察和记录，不选择节点。用户在仪表盘卡片中显式开启自动路由后，脚本才允许通过 Clash External Controller 的 PUT 选择接口。`route_group` 表示要监控的候选组，但它可能是 `URLTest` 子组，不一定是实际出站选择组；脚本会读取 `/proxies` 和 `/rules`，沿当前 `MATCH` 规则解析真正承载默认流量的 `Selector`，只对该 Selector 写入。

自动路由规则是：

1. 当前节点仍为绿色时保持不动，即使它不是延迟第一名。
2. 当前节点变为橙色时，必须连续达到 route_after_failures，且存在绿色候选，才切换到绿色候选中延迟最低的节点；当前节点首次完整采样为 Timeout 或 error 时，只要存在绿色候选就立即故障转移，不等待第二次确认。
3. 写入前重新读取实际出站组；如果用户在评估期间手动改变了 Clash，当前轮放弃写入并同步新选择，不覆盖用户操作。
4. PUT 后同时回读控制 Selector 和最终有效节点；两者不一致就判定切换失败，不把计划目标伪装成成功。
5. 成功切换后记录 route_cooldown_seconds；它不阻挡橙色达到确认次数后的切换，也不阻挡首次确认的超时或错误故障转移，避免当前节点已失速时卡在旧冷却期。没有绿色候选、控制器异常或切换失败时只记录原因，不循环重试。
6. 路由动作写入本地 route_events，并在周期结果中公开 action、from、to 和 message，便于审计。

## 独立 Web 控制台

`py tw_monitor.py --server` 同时承担采样进程、JSON API 和静态页面服务，浏览器入口为 `http://127.0.0.1:17997/`。静态文件只允许从项目内 `web/` 目录读取，路径穿越请求不会落到源码目录；接口和页面同源，因此用户无需配置 CORS、反向代理或前端开发环境。

页面的读取路径是：

1. `/api/status` 提供当前完整周期、节点清单、实际 Clash 路由和运行状态。
2. `/api/history` 提供按日期和聚合粒度整理后的历史序列。
3. `/api/export?days=1|3|7` 返回当前时间范围内的原始 UTF-8 CSV；导出字段稳定，不受趋势图展示聚合影响。
4. 页面以当前健康度、实际出站节点、趋势图和节点表为第一视图；只有用户明确提交设置或开启自动路由时才发起写操作。

原 Obsidian 卡片仍可读取同一组 JSON API；独立版不依赖其桥接层，也不复制 Vault Markdown、SQLite 或本机密钥。两种入口共用同一服务时只能启动一个监听端口，避免产生两个采样器。

## 并发与资源

每轮只使用一个监控线程和默认 4 个短请求线程，周期结束后才安排下一轮，避免节点不稳定时请求堆积。loopback 服务只监听本机；浏览器页面和浮点都只轮询本机摘要，不额外创建采样线程。SQLite 使用单写者、短连接和索引，旧数据按保留天数清理。

接口职责：

| 接口 | 用途 | 是否写入 Clash |
| --- | --- | --- |
| GET /api/health | 服务探活 | 否 |
| GET /api/status | 最近完整周期、节点列表、从 Clash 直读的实际路由状态 | 否 |
| GET /api/history?date=YYYY-MM-DD | 指定日期的折线图序列；卡片组合多个日期形成 1/3/7 天历史 | 否 |
| GET /api/export?days=1\|3\|7 | 导出当前时间范围的原始 UTF-8 CSV，供人工或 AI 分析 | 否 |
| POST /api/refresh | 请求一次完整刷新；已有刷新时返回 busy | 否 |
| POST /api/pause | 暂停或继续周期调度 | 否 |
| POST /api/settings | 修改本地采样和路由设置 | 否 |
| POST /api/shutdown | 关闭本地服务 | 否 |
| GET /、/index.html、/styles.css、/app.js | 提供独立 Web 控制台静态资源 | 否 |

Obsidian 卡片只读取这些 loopback JSON，不写 Vault Markdown，不复制 SQLite。独立 Web 控制台和卡片都可读取 1/3/7 天历史；前端将按日期合并为默认 30 分钟聚合的 SVG 线图，降低后台渲染压力；用户仍可手动选择 1 分钟、30 秒或其他聚合粒度查看细节，这不会改变后台按设置间隔写入 SQLite 的采样频率。图表默认聚焦一个节点，并提供时间缩放和拖拽/键盘平移。两种形态共用一个服务和同一份数据。

## 发布边界

可分发内容为 `tw_monitor.py`、`web/`、`run_monitor.bat`、`monitor_config.example.json`、`README.md`、`docs/` 和测试文件。不得分发 `monitor_config.json`、API 密钥、`data/tw_monitor.sqlite3`、`__pycache__` 或其他本机运行产物；使用者首次启动时才生成自己的配置和数据库。

## 配置优先级

1. 命令行参数。
2. 项目目录下未跟踪的 `monitor_config.json`。
3. `CLASH_SECRET` 环境变量和 `CLASH_CONFIG_PATH` 环境变量。
4. Clash Verge 常见配置路径中的 `config.yaml`。
5. 内置安全默认值。

配置读取是单向的；不会回写 Clash 配置文件。只有用户在卡片中开启自动路由且满足条件时，才通过控制器临时修改运行中的 Selector 选择，并立即回读确认。
