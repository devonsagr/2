# 架构说明

## 1. 组件

```text
Clash / mihomo External Controller
              │  节点清单、delay、实际路由状态
              ▼
      clash_node_monitor.py
       ├─ 采样服务与完整周期快照
       ├─ SQLite 历史与路由事件
       ├─ loopback JSON API
       └─ 可选桌面浮点 / 无界面入口
              │
              ▼
       web/index.html + styles.css + app.js
       ├─ 连接引导与测试
       ├─ 当前状态与节点明细
       ├─ 1/3/7 天趋势
       ├─ 原始 CSV 导出
       └─ 设置、暂停、刷新、停止
```

EXE 由 PyInstaller 生成，包含 Python 运行时和 `web/` 静态资源。启动 EXE 后由 Python 监听本机端口，并自动打开系统浏览器；浏览器不是数据服务，只是控制台界面。

## 2. 数据边界

- 监控服务直接调用 External Controller，不模拟鼠标，也不依赖 Clash 图形界面。
- 默认绑定 `127.0.0.1`；控制器密钥只在本机配置和进程内存中使用，不进入前端 JSON。
- 每个完整采样周期先收集所有节点结果，再一次性替换最近快照，避免页面看到半轮数据。
- SQLite 保存明细、每日历史和自动路由事件；默认保留 30 天。
- `/api/export` 只生成本机下载响应，不上传或调用 AI。

## 3. 运行配置

配置优先级：命令行参数 → 项目目录下的 `monitor_config.json` → `CLASH_SECRET` / `CLASH_CONFIG_PATH` 环境变量 → 常见本机 Clash 配置 → 内置默认值。

首次使用不要求手写配置：控制台先显示自动发现状态；用户可以在“连接高级设置”输入控制器地址、密钥并测试，保存后才写入本机配置。

公开模板的节点筛选默认是 `.*`，即监控所有可识别叶子节点。策略组、URLTest 和 LoadBalance 只作为容器，不作为独立节点采样；用户可以用正则或勾选清单缩小范围。

## 4. API

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/api/status` | 服务状态、设置摘要、节点清单、最近完整周期和实际路由状态 |
| GET | `/api/history?date=YYYY-MM-DD&bucketSeconds=...` | 指定日期的趋势序列 |
| GET | `/api/export?days=1\|3\|7` | 导出当前时间范围的原始 UTF-8 CSV |
| POST | `/api/connection-test` | 用当前或临时地址/密钥探测控制器，不保存临时值 |
| POST | `/api/refresh` | 请求一次完整采样 |
| POST | `/api/pause` | 暂停或继续周期调度 |
| POST | `/api/settings` | 修改本机采样、连接和路由设置 |
| POST | `/api/shutdown` | 关闭本机服务 |
| GET | `/`、`/index.html`、`/styles.css`、`/app.js` | 提供控制台静态资源 |

## 5. 自动路由边界

自动路由默认关闭。用户明确开启并填写监控候选组后，服务才会在连续异常、绿色候选和控制器实际状态满足条件时调用选择接口；写入后必须 GET 回读最终节点。关闭自动路由时，所有采样只读。

## 6. 发布边界

公开发布包括源码、`web/`、测试、文档、示例配置、启动脚本和 `release/ClashNodeMonitor.exe`。不得发布真实 `monitor_config.json`、API 密钥、`data/*.sqlite3`、缓存或构建临时目录。
